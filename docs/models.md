## Introduction

migro includes an object-relational mapper in the spirit of Laravel's Eloquent and AdonisJS's Lucid. Each table has a **model** that you use to work with it: retrieve rows, insert, update and delete them, and follow [relations](relations.md) to other tables.

A model is a GORM struct that embeds `orm.BaseModel`. `orm.New[User](db)` is its repository, the counterpart of `User::` in Eloquent: it finds, queries and creates. The models it returns are **bound** to the database, so they have an instance API as well (`user.Save(ctx)`, `user.Posts.Get(ctx)`).

## Generating model classes

```
migro make:model Flight
```

writes `app/models/flight.go` (`MIGRO_MODELS_DIR`). Other files can be created with it:

| Flag | Also creates |
|---|---|
| `-m` | a migration (`create_flights_table`) |
| `-f` | a factory |
| `-s` | a seeder |
| `-a` | all three |
| `--uuid`, `--ulid` | a model with a string key ([below](#uuid-and-ulid-keys)) |
| `--from-table=flights` | the struct read from the live table: column types, nullable pointers, `gorm` tags |

Laravel's controller, policy, request and resource flags have no counterpart; `migro make:resource Flight` writes an [API resource](resources.md).

#### Inspecting models

```
migro model:show Flight
```

prints the model's table, columns, relations and the optional behaviours it implements. `orm.Describe(db, &Flight{})` returns the same as a value.

## Model conventions

A model generated by `make:model`:

```go
package models

type Flight struct {
    orm.BaseModel // ID, CreatedAt, UpdatedAt
    Name    string
    Airline string
}
```

### Table names

The table is the snake_case plural of the type name, GORM's convention: `Flight` uses `flights`, `AirTrafficController` uses `air_traffic_controllers`. To use another table, add a `TableName` method:

```go
func (Flight) TableName() string { return "my_flights" }
```

### Primary keys

The key is the field named `ID`, or the one tagged `gorm:"primaryKey"`. `BaseModel` gives you an auto-incrementing `uint` `ID`. For another column:

```go
type Flight struct {
    orm.Record
    FlightID  uint `gorm:"primaryKey"`
    CreatedAt time.Time
    UpdatedAt time.Time
}
```

`orm.Record` carries the instance methods without any column, for models that define their own.

#### "Composite" primary keys

As in Eloquent, a model needs one primary key to be saved, refreshed and deleted on its own. A table with a composite key (a pivot table, say) still works as the related side of a relation, through `orm.Bind`, and with the query builder; it cannot embed `BaseModel`.

### UUID and ULID keys

Embed `orm.UUIDModel` (UUID version 7, ordered by time) or `orm.ULIDModel` instead of `BaseModel` for a string key:

```go
type Article struct {
    orm.UUIDModel
    Title string
}

a := &Article{Title: "Traveling to Europe"}
err := orm.New[Article](db).Create(ctx, a)
a.ID // "018f6a2c-...", generated on insert
```

The key is generated on insert when it is empty; one you set is kept. `orm.SoftDeleteUUIDModel` and `orm.SoftDeleteULIDModel` add soft deletes. Foreign keys that point at these models are plain `string` columns. `orm.NewUUID()` and `orm.NewULID()` generate values directly, and `make:model Article --uuid` (or `--ulid`) scaffolds the model.

`orm.UUIDKey` and `orm.ULIDKey` are the bare key columns, for a model that brings its own timestamps: embed `orm.Record` next to them for the instance methods.

`Find`, `FindMany` and `Destroy` name the primary key column themselves, so string keys work there. (GORM alone would read a non-numeric string passed to `First` as raw SQL.)

### Timestamps

`BaseModel` has `CreatedAt` and `UpdatedAt`, set by GORM on insert and update. A model without timestamps embeds `orm.Record` and declares only its key. To use other column names, tag the fields:

```go
type Flight struct {
    orm.Record
    ID           uint      `gorm:"primaryKey"`
    CreationDate time.Time `gorm:"autoCreateTime"`
    UpdatedDate  time.Time `gorm:"autoUpdateTime"`
}
```

To save without touching `updated_at` (Laravel's `withoutTimestamps`), use `SaveWithoutTimestamps`, which skips events and hooks too. `Touch` updates `updated_at` only.

### Database connections

A model uses the database its repository was made with. With a [`Manager`](connecting.md#using-multiple-database-connections), a model can name its connection, and `orm.Using` follows it:

```go
func (Flight) Connection() string { return "sqlite" }

flights, err := orm.Using[Flight](ctx, mgr)
```

### Default attribute values

`Defaults` gives a model its starting values (Eloquent's `$attributes`):

```go
func (Flight) Defaults() map[string]any { return map[string]any{"delayed": false, "options": "[]"} }

flight, err := orm.New[Flight](db).Make(map[string]any{"name": "Paris"}) // Delayed == false
```

Defaults apply in `Make` and `CreateFrom`, before the attributes you pass. A struct literal is never touched: Go cannot tell a field left at its zero value from one set to it.

### Configuring strictness

`db.ShouldBeStrict(true)` makes lazy loading fail, so N+1 queries show up in development (Eloquent's `preventLazyLoading`). Mass assignment of an unknown or guarded column always fails in migro, where Eloquent drops it silently unless `preventSilentlyDiscardingAttributes` is on. See [Strict mode and debugging](strict-mode.md).

## Retrieving models

The repository is a query builder for the model's table:

```go
flights := orm.New[Flight](db)

all, err := flights.All(ctx)
for _, f := range all {
    fmt.Println(f.Name)
}
```

#### Building queries

`Query()` starts a query with constraints; `Get` runs it:

```go
list, err := flights.Query().
    Where("active = ?", true).
    OrderBy("name", "asc").
    Limit(10).
    Get(ctx)
```

Every method of the [query builder](query-builder.md) is available, and the models it returns are bound.

#### Refreshing models

`orm.Fresh` loads a model again from the database into a new value, leaving the original as it is. `Refresh` reloads the model in place:

```go
fresh, err := orm.Fresh(ctx, flight)

flight.Number = "FR 900"
err = flight.Refresh(ctx) // flight.Number is back to its stored value
```

To reload with a row lock, query inside a transaction with `LockForUpdate` ([locking](query-builder.md#pessimistic-locking)).

### Collections

Methods that return several models (`All`, `Get`, relations) return an `orm.Collection[T]`, a slice with model-aware methods:

```go
active := all.Filter(func(f *Flight) bool { return !f.Cancelled })
byID, err := all.KeyBy("id")
```

It is still a slice, so `range` and `len` work. See [Collections](collections.md).

### Chunking results

Loading tens of thousands of models at once would use a lot of memory. `Chunk` takes them in batches:

```go
err := flights.Query().Chunk(ctx, 200, func(batch []Flight) error {
    for _, f := range batch {
        ...
    }
    return nil
})
```

When the callback updates the column you filter on, use `ChunkByID`, which pages by key, so updated rows are not skipped:

```go
err := flights.Query().Where("departed = ?", true).ChunkByID(ctx, 200, "id", func(batch []Flight) error {
    ids, err := orm.Collection[Flight](batch).ModelKeys()
    if err != nil {
        return err
    }
    _, err = flights.Query().WhereIn("id", ids).Update(ctx, map[string]any{"departed": false})
    return err
})
```

### Chunking using lazy iterators

`Lazy` is a flat iterator over the same chunks, with eager loading:

```go
for flight, err := range flights.Query().With("Pilot").Lazy(ctx, 200) {
    if err != nil {
        return err
    }
    ...
}
```

### Cursors

`Cursor` runs a single query and builds one model at a time as rows arrive, which uses the least memory:

```go
for flight, err := range flights.Query().Where("destination = ?", "Zurich").Cursor(ctx) { ... }
```

It cannot eager load relations; use `Lazy` when you need them. `Each(ctx, size, fn)` is the callback form of `Lazy`. Breaking out of a loop releases the statement.

### Advanced subqueries

#### Subquery selects

Select a value from a related table as an extra column (Eloquent's `addSelect` with a subquery):

```go
destinations, err := orm.New[Destination](db).Query().
    Select("destinations.*",
        "(SELECT name FROM flights WHERE flights.destination_id = destinations.id ORDER BY arrived_at DESC LIMIT 1) AS last_flight").
    Get(ctx)
```

Read the extra column with `d.Extra("last_flight")`. For counts and sums over relations, `WithCount` and `WithSum` do this for you ([Relations](relations.md#aggregating-related-models)).

#### Subquery ordering

```go
q.Scope(func(g *gorm.DB) *gorm.DB {
    return g.Order("(SELECT MAX(arrived_at) FROM flights WHERE flights.destination_id = destinations.id) DESC")
})
```

## Retrieving single models and aggregates

```go
flight, err := flights.Find(ctx, 1)                        // by primary key
flight, err = flights.Query().Where("active = ?", true).First(ctx)
flight, err = flights.Query().FirstWhere(ctx, "active", true)
flight, err = flights.FindBy(ctx, "number", "FR 900")
many, err := flights.FindMany(ctx, 1, 2, 3)                // missing ids are absent
```

`Find` and `First` return a `NOT_FOUND` error when nothing matches; check it with `errors.Is(err, migro.ErrNotFound)`. Laravel's `findOr` and `firstOr` are that check:

```go
flight, err := flights.Find(ctx, id)
if errors.Is(err, migro.ErrNotFound) {
    flight, err = fallback(ctx)
}
```

#### Retrieving single column values

```go
name, err := orm.Value[Flight, string](ctx, flights.Query().Where("legs > ?", 3), "name")
flight, err := flights.Query().Where("number = ?", n).Sole(ctx) // NOT_FOUND or MULTIPLE_RECORDS_FOUND
```

#### Not found errors

`FindOrFail` and `FirstOrFail` behave like `Find` and `First`, with Laravel's names. In an HTTP handler, map the error to a 404:

```go
flight, err := flights.FindOrFail(ctx, id)
if errors.Is(err, migro.ErrNotFound) {
    http.NotFound(w, r)
    return
}
```

### Retrieving or creating models

`FirstOrCreate` finds a row matching the non-zero fields of its first argument, or inserts one from both arguments. `FirstOrNew` does the same without saving:

```go
flight, created, err := flights.FirstOrCreate(ctx, Flight{Name: "London to Paris"}, Flight{Delayed: true, ArrivalTime: "11:30"})

flight, exists, err := flights.FirstOrNew(ctx, Flight{Name: "Tokyo to Sydney"}, Flight{Delayed: true})
if !exists {
    err = flights.Create(ctx, flight)
}
```

### Retrieving aggregates

```go
n, err := flights.Query().Where("active = ?", true).Count(ctx)
max, err := flights.Query().Where("active = ?", true).Max(ctx, "price")
sum, err := flights.Query().Sum(ctx, "price")
ok, err := flights.Query().Where("number = ?", number).Exists(ctx)
```

## Inserting and updating models

### Inserts

Build the struct and pass it to `Create`. `created_at` and `updated_at` are set for you, and the key is filled in:

```go
flight := &Flight{Name: r.FormValue("name")}
if err := flights.Create(ctx, flight); err != nil {
    return err
}
flight.ID // set
```

`CreateFrom` builds the model from a map, through [mass assignment](#mass-assignment), and saves it (Eloquent's `create`). `CreateMany` inserts a slice in one statement:

```go
flight, err := flights.CreateFrom(ctx, map[string]any{"name": "London to Paris"})
err = flights.CreateMany(ctx, []Flight{ {Name: "A"}, {Name: "B"} })
```

`Make` builds a model from a map without saving it, and `flights.Save(ctx, flight)` saves one you built yourself.

### Updates

Change the fields of a bound model and call `Save`. Only the changed columns are written, `updated_at` is set, and a model with no changes is not written at all:

```go
flight, err := flights.Find(ctx, 1)
flight.Name = "Paris to London"
err = flight.Save(ctx) // UPDATE flights SET name = ?, updated_at = ? WHERE id = 1
```

`Update` assigns a map, then saves:

```go
err = flight.Update(ctx, map[string]any{"name": "Paris to London"})
```

`UpdateOrCreate` finds a row by the first argument and updates it from the second, or creates it:

```go
flight, err := flights.UpdateOrCreate(ctx,
    Flight{Departure: "Oakland", Destination: "San Diego"},
    Flight{Price: 99, Discounted: true},
)
```

#### Bound models

A model is bound when it comes from `Find`, `Get`, `First`, `Paginate`, `Create*`, a relation or a factory. A struct you build yourself is not: create it through the repository, build it with `Make`, or call `orm.Bind(db, &flight)`. `Save` on an unbound model returns `UNBOUND_MODEL`.

Go copies structs by value, and a copy is detached from the row it came from. Keep pointers (`&rows[0]`, not `row := rows[0]`) when you use the instance API after loading.

#### Mass updates

Update every row that matches a query:

```go
n, err := flights.Query().
    Where("active = ?", true).
    Where("destination = ?", "San Diego").
    Update(ctx, map[string]any{"delayed": true})
```

`n` is the number of rows changed.

{: .warning }
A mass update does not load the models, so **no model events fire** for it (`saving`, `saved`, `updating`, `updated`).

#### Increment and decrement

```go
err := flight.Increment(ctx, "seats_sold", 1)
err = flight.Decrement(ctx, "seats_left", 1)
err = flight.IncrementEach(ctx, map[string]int{"seats_sold": 2, "bookings": 1}) // one atomic update
n, err := flights.Query().Where("id = ?", 1).Increment(ctx, "seats_sold", 1)
```

#### Examining attribute changes

`IsDirty` and `IsClean` tell whether fields changed since the model was loaded; `Dirty` lists them:

```go
user, _ := users.Query().FirstWhere(ctx, "email", "taylor@example.com")
user.Title = "Painter"

user.IsDirty()                      // true
user.IsDirty("title")               // true
user.IsDirty("first_name")          // false
user.IsDirty("first_name", "title") // true: any of them
user.IsClean("first_name")          // true
user.Dirty()                        // map[title:Painter]

_ = user.Save(ctx)
user.IsDirty()                      // false
```

`WasChanged` and `GetChanges` describe the **last save**; `GetOriginal` returns the value the model was loaded with:

```go
user.WasChanged()          // true
user.WasChanged("title")   // true
user.GetChanges()          // map[title:Painter updated_at:...]
user.GetOriginal("title")  // the title as it was loaded
user.WasRecentlyCreated()  // true when that Save inserted the row
```

### Mass assignment

`Fill`, `Update`, `Make` and `CreateFrom` take a map of column (or field) names to values. Passing request data straight to them is a classic hole: a user could add `is_admin=true` to a form. Say which columns may be assigned:

```go
func (Flight) Fillable() []string { return []string{"name", "airline"} } // Eloquent's $fillable
// or
func (Flight) Guarded() []string { return []string{"is_admin"} }        // Eloquent's $guarded
```

`Guarded` is ignored when `Fillable` exists. With neither method, every column is assignable (Eloquent's `#[Unguarded]`), so build the map yourself rather than copying a request.

#### Mass assignment errors

A key that is guarded, not fillable, or not a column fails with `MASS_ASSIGNMENT`, and nothing is assigned. Eloquent drops such keys silently by default; migro never does.

```go
_, err := flights.CreateFrom(ctx, map[string]any{"name": "X", "is_admin": true})
// migro.CodeOf(err) == migro.MassAssignment
```

#### Mass assignment and JSON columns

Laravel lets `options->enabled` be fillable. In migro a JSON column is assigned as a whole; see [JSON casting](mutators-casting.md#array-and-json-casting).

### Upserts

`Upsert` inserts rows and updates the ones that already exist, in one statement:

```go
err := flights.Upsert(ctx, []Flight{
    {Departure: "Oakland", Destination: "San Diego", Price: 99},
    {Departure: "Chicago", Destination: "New York", Price: 150},
}, []string{"departure", "destination"}, []string{"price"})

err = flights.Upsert(ctx, rows, []string{"slug"}, nil) // update every column except the keys
```

The second argument identifies existing rows and needs a primary key or unique index (except on SQL Server). MySQL and MariaDB ignore it and use whichever unique key conflicts. PostgreSQL, MySQL and SQLite use their own `ON CONFLICT` form. SQL Server and Oracle have none, so `Upsert` writes a `MERGE`, in batches, filling UUID keys and timestamps as `Create` would. Redshift has no upsert (`UNSUPPORTED_FEATURE`).

`UpdateOrCreateMany(ctx, keys, rows)` is the model-by-model form, in one transaction: it never rewrites the primary key, `created_at` or `deleted_at`, so a soft-deleted row is not brought back. `FirstOrCreateMany` leaves existing rows alone. `InsertOrIgnore` skips rows that break a unique key.

## Deleting models

```go
flight, err := flights.Find(ctx, 1)
err = flight.Delete(ctx)
```

#### Deleting an existing model by its primary key

```go
n, err := flights.Destroy(ctx, 1)
n, err = flights.Destroy(ctx, 1, 2, 3)
n, err = flights.Destroy(ctx, ids...)
```

{: .note }
Laravel's `destroy` loads each model and fires its events. migro's `Destroy` deletes with one statement, so no model events fire. Load the models and call `Delete` on each when you need the events.

#### Deleting models using queries

```go
n, err := flights.Query().Where("active = ?", false).Delete(ctx)
err = flights.Truncate(ctx) // every row
```

A query delete without a `Where` is refused instead of deleting every row; `Truncate` is the explicit way. Query deletes fire no model events either.

### Soft deleting

A soft-deleted row stays in the table with a `deleted_at` time, and queries leave it out. Embed `orm.SoftDeleteModel` instead of `BaseModel`, and add the column with `t.SoftDeletes()` in the migration:

```go
type Flight struct {
    orm.SoftDeleteModel // ID, CreatedAt, UpdatedAt, DeletedAt
    Name string
}
```

`Delete` then sets `deleted_at` instead of removing the row, and every query skips trashed rows. To check a model:

```go
if flight.Trashed() { ... }
```

#### Restoring soft deleted models

```go
err := flight.Restore(ctx)
```

To restore many at once, update the column through a query that includes trashed rows (no events fire):

```go
_, err := flights.Query().WithTrashed().Where("airline_id = ?", 1).Update(ctx, map[string]any{"deleted_at": nil})
```

#### Permanently deleting models

```go
err := flight.ForceDelete(ctx)
```

### Querying soft deleted models

#### Including soft deleted models

```go
all, err := flights.Query().WithTrashed().Where("account_id = ?", 1).Get(ctx)
```

#### Retrieving only soft deleted models

```go
gone, err := flights.Query().OnlyTrashed().Get(ctx)
```

`OnlyTrashed` assumes the column is `deleted_at`.

## Pruning models

To delete rows that are no longer needed on a schedule, say which rows are stale (Eloquent's `Prunable`):

```go
func (Session) Prunable(q *orm.Query[Session]) *orm.Query[Session] {
    return q.Where("expires_at < ?", time.Now())
}

// optional: runs before each model is deleted, for example to remove files
func (s *Session) Pruning(ctx context.Context) error { return storage.Delete(ctx, s.FilePath) }
```

Register the model, then run the command daily from cron, a Kubernetes CronJob or a ticker:

```go
orm.RegisterPrunable[Session]("sessions")
```

```
migro model:prune
```

From Go, `orm.New[Session](db).Prune(ctx)` prunes one model and `orm.PruneAll(ctx, db)` every registered one. A `Prunable` model is deleted row by row, for good (soft-deleted rows included), with model events and the `Pruning` hook.

#### Mass pruning

`MassPrunable` deletes the stale rows with one statement. It is much faster, but `Pruning` is not called and no model events fire.

## Replicating models

`orm.Replicate` copies a model into a new, unsaved one:

```go
billing, err := orm.Replicate(ctx, shipping)
billing.Type = "billing"
err = billing.Save(ctx)
```

The copy loses its primary key, timestamps, soft-delete mark and loaded relations. List columns to clear as well:

```go
copy, err := orm.Replicate(ctx, flight, "last_flown", "last_pilot_id")
```

`before:replicate` listeners can stop it ([Events](events.md)).

## Query scopes

Scopes are reusable constraints. Local scopes are functions you apply (`Apply(Popular, Active)`); global scopes apply to every query of a model, as soft deletes do. See [Query scopes](query-scopes.md).

## Comparing models

`orm.Is(a, b)` reports whether two models are the same row: the same type and the same non-zero primary key. `orm.IsNot` negates it:

```go
if orm.Is(post, otherPost) { ... }
```

## Events

Models fire events through their life: retrieved, creating and created, updating and updated, saving and saved, deleting and deleted, restoring and restored, force deleting and force deleted, replicating. Listen with closures or observers, and mute them with `SaveQuietly` and `DeleteQuietly`. See [Events](events.md).
